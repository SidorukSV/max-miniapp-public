# Единый чат и уведомления о записи — 1.1.0.35

Расширение предназначено для полной интеграции миниаппа «БИТ.Медицина / Омни: ПРОФ»
и БИТ.Управление медицинским центром КОРП 2.1.25.76. Обновление backend/frontend
для этих изменений не требуется.

## Поведение

- Дата и время ближайшей записи в Едином чате открывают соответствующую заявку.
- Кнопка «Расписание клиента» открывает стандартный отчёт из карточки клиента.
- При создании записи отправляется отдельное уведомление без кнопок:
  «Имя Отчество, вы записаны на приём 15 октября 2026, Чт 09:05.
  Врач: … Просим Вас подходить на прием заранее, с собой необходимо иметь паспорт.»
- Запрос подтверждения отправляется за 24 часа до приёма. Если запись на завтра
  создана менее чем за сутки, запрос ставится на ближайший запуск очереди.
- Запись на сегодняшний день автоматически подтверждается при сохранении,
  запрос с кнопками для неё не отправляется. Дата определяется по времени сеанса 1С.
- При переносе времени создаётся новый цикл уведомлений, ожидающие сообщения
  о прежнем времени пропускаются.
- Дополнительные напоминания из интервалов бота отправляются без кнопок.
  Интервал 24 часа обслуживается отдельным запросом подтверждения, без дубля.
- Нажатия «Подтвердить» и «Отменить» показываются в истории как
  «ДЕЙСТВИЕ КОНТАКТА» с результатом обработки. Повтор webhook не дублирует действие.
  Кнопка `open_app`, открывающая миниапп, не порождает callback о самом нажатии.
- Нажатие уведомления о новом сообщении открывает нужный диалог. Черновик другого
  пациента сохраняется в отдельном экземпляре чата.

Отправка выполняется регламентным заданием «ОМНИ: очередь и напоминания MAX»:
ожидаемое отклонение времени отправки — до одного интервала его запуска.

## Установка и настройка

1. Сделайте резервную копию базы и сохраните прежнее расширение.
2. Установите CFE 1.1.0.35 взамен полного расширения Омни, обновите конфигурацию
   базы и перезапустите сеансы пользователей и HTTP-публикации по принятому порядку.
3. Проверьте настройку УМЦ «Признак подтвержденной заявки». Поддерживаются
   состояние заявки и свойство из регистра «Значения свойств объектов».
   При пустой настройке сохранение новой записи на сегодня выдаст понятную ошибку:
   автоматическое подтверждение невозможно. Настройте признак до проверки записи.
4. В стандартных шаблонах повторно загрузите **выбранные** шаблоны
   `MAX_APPOINTMENT_CREATED`, `MAX_APPOINTMENT_CONFIRM_REQUEST`,
   `MAX_APPOINTMENT_REMINDER`, `MAX_APPOINTMENT_REMINDER_CONFIRMED`.
   Перезагрузка заменяет текст, алгоритмы полей и кнопки этих шаблонов:
   предварительно сохраните индивидуальные тексты клиники.
5. В карточке нужного бота выполните «Настроить рассылки записей» и выберите
   «Скорректировать существующие». В предпросмотре должен появиться новый сценарий
   «Новая запись без кнопок», а запрос подтверждения — остаться отдельным сценарием.
   Проверяйте конфликты и общие рассылки других ботов перед применением.
6. Убедитесь, что регламентное задание активно. Не запускайте обработку старых
   строк со статусом «Ошибка» массово без проверки причин и актуальности заявок.

Само обновление расширения не перезаписывает пользовательские шаблоны и не
активирует новый сценарий. Старые ожидающие немедленные запросы и напоминания
за 24 часа пропускаются обработчиком, чтобы не задвоить новую рассылку.

## Приёмочная проверка на тестовом пациенте

Проводить в согласованной тестовой базе/боте: создание записей меняет данные,
активные рассылки отправляют реальные сообщения.

1. Создать запись через 3 дня: сразу только сообщение без кнопок; запрос — за сутки.
2. Создать запись на завтра менее чем за сутки: информационное сообщение и отдельный
   запрос с кнопками в ближайшем запуске очереди.
3. Создать запись на сегодня: признак подтверждения установлен, приходит только
   сообщение о записи. Проверить оба варианта признака: состояние и свойство.
4. Повторно сохранить тот же объект, отменить и перенести дату: остаточный флаг
   автоподтверждения не должен восстанавливать подтверждение.
5. Перенести будущее время приёма: сообщение содержит новое время, старая очередь
   не отправляет запрос о прежнем времени.
6. Нажать обе поддерживаемые callback-кнопки на отдельных заявках: оператор видит
   действие и результат, повторная доставка того же callback не создаёт дубль.
7. Открыть заявку и расписание клиента из чата; проверить выбор правильного пациента.
8. Нажать уведомление при открытом/закрытом чате, поиске, отборе и черновике другого
   пациента: открывается нужный диалог, чужой черновик не переносится.

Автоматические проверки календарной логики и русского формата даты:
`python -m unittest discover -s onec/omni/tests -v` (требуется установленный OneScript).
Они исполняют извлечённые функции BSL без подключения к базе и отправки сообщений;
не заменяют приёмочную проверку интерфейса и событий в 1С.

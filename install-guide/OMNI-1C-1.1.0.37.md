# Непривязанные контакты Единого чата — 1.1.0.37

Изменение полного расширения «БИТ.Медицина / Омни: ПРОФ». Обновление
backend/frontend миниаппа для него не требуется.

## Поведение

- При запуске бота или новом входящем сообщении непривязанный контакт получает
  запрос номера, если этому контакту от этого бота ещё не отправляли успешное
  сообщение с кнопкой `request_contact`. Повторные сообщения не дублируют запрос.
- Полученный контакт сначала проходит штатную проверку подписи и привязку.
  После успешной привязки дополнительный запрос номера не отправляется.
- Учитываются ранее отправленные запросы независимо от текста шаблона.
  Неуспешная отправка допускает новую попытку при следующем входящем событии.
- Если шаблон `MAX_WELCOME` отсутствует либо не содержит кнопки запроса контакта,
  используется встроенное сообщение с такой кнопкой.
- Единый чат показывает и контакты без пациента: каждый отдельно, под именем MAX.
  Для них доступны переписка и ручная привязка пациента. Состояние и ответственный
  диалога пациента становятся доступны после привязки.
- В непривязанном диалоге выберите пациента и нажмите «Привязать пациента».
  История остаётся у исходного контакта и включается в общий диалог пациента с
  этим ботом. Уже существующую привязку эта команда не заменяет.
- Контакт без сообщений открывается с пустой историей. Отсутствующая дата
  сообщения больше не участвует в сравнении как `NULL`.

## Установка и проверка

1. Сохраните резервную копию базы и прежнее расширение. Установите полное CFE
   1.1.0.37 взамен прежней версии Омни и перезапустите сеансы и HTTP-публикацию
   по принятому порядку.
2. Перезагрузка шаблонов и настройка рассылок для этой доработки не нужны.
   Предыдущие исправления входят в обновление; при переходе с версии до 1.1.0.36
   выполните также её [инструкцию](OMNI-1C-1.1.0.36.md).
3. На согласованном тестовом контакте без пациента и истории откройте чат:
   диалог должен отображаться без ошибки сравнения.
4. Отправьте сообщение от тестового пользователя: запрос номера должен прийти
   один раз, а повторное сообщение не должно порождать ещё один запрос.
5. Проверьте штатную авторизацию через кнопку передачи контакта, затем отдельно
   ручную привязку другого тестового контакта. Проверьте сохранность истории,
   открытие диалога из уведомления и отсутствие смешивания двух непривязанных
   контактов.

Само открытие чата не запускает рассылку запросов по старым контактам.
Для существующего непривязанного контакта запрос будет проверен при следующем
входящем сообщении или запуске бота. Ручная привязка изменяет данные контакта,
поэтому выбирайте пациента после проверки личности собеседника.

Автоматические тесты запускаются командой
`python -m unittest discover -s onec/omni/tests -v` при установленном OneScript.
Фикстуры не заменяют приёмочную проверку в клиентской базе с реальным ботом.
